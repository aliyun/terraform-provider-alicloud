# 写周报

## 核心原则

### 1. 价值视角，不是活动视角

- ❌ 不按仓库分块（cloudspec / automation_agent / acube 各一段）
- ✅ 按对外可交付价值分块（MCP Server RunIaC 上线 / 工具体系对内门户 PlayGround 上线 / Terraform AutoPilot 能力建设）
- 同一价值方向横跨多个仓的工作合并写

### 2. 先确定具体汇报主体

开始采集前必须明确汇报主体的姓名和工号，并据此建立代码身份、Aone 身份和常用别名集合：

```bash
bin/a1id -- staff list <姓名>
```

- 用户说“我的周报”时，使用当前对话中可验证的用户身份；无法确认姓名或工号时，先询问，不得默认套用某个固定人员。
- 用户指定他人时，以该具体人员为汇报主体。
- 后文的“本人”均指本次已明确的汇报主体，不是 Skill 作者、执行 Agent 或服务账号。

### 3. 个人归因门：参与且产生结果

个人周报中的每条事项必须同时满足以下三项，缺一不写：

1. **本人参与证据**：存在汇报主体本人在统计周期内的 commit / MR / PR，或 Aone 评论中的明确方案、评审、测试指导、决策、问题定界、跨团队协调等动作。
2. **后续结果证据**：本人动作之后出现可验证结果，例如合入、CI/AccTest 通过、缺陷修复、方案定稿、阻塞解除、需求范围收敛或明确的下一阶段交付物。
3. **因果时序成立**：参与证据早于结果证据，且两者针对同一问题。项目整体进度或时间上的巧合不能归因给本人。

允许把非编码贡献写入周报，但措辞必须匹配真实角色：

- 本人未直接提交代码，但通过评审、验收或决策促成结果：写“推动验收收口”“主导方案决策”“定位并推动修复”。
- 只有本人有代码提交证据时，才写“开发”“实现”。
- open-jarvis / Terraform-研发数字人等服务账号的执行结果不自动归属于汇报主体；只有 Aone 中存在汇报主体本人的明确指令、评审或决策，且随后产生对应结果时，才能写成该主体的推进成果。

以下内容只作为候选线索，不能单独证明个人产出：

- Aone 的 assignee / tracker / participant 字段；
- 标题含某项目名、项目汇总单、看板统计或批量状态变化；
- 他人完成的代码、测试、评审或合入；
- 自动机器人评论、自动状态同步、仅更新控制面完成态；
- 只有催办或“看下”，但后续没有实际结果；
- 本人在项目中承担 owner，但该事项本周没有本人动作。

### 4. 基础设施工具不当主线

- 内部支撑工具（Jarvis 自治、a1id 多身份、钉钉桥）不要展开技术细节
- 写"用它交付了多少需求"，不写"我搭了什么模块"

### 5. 粒度纪律

| 项 | 上限 |
|---|---|
| 一级方向 | 3-5 个，绝不超过 7 |
| 每方向子项 | 2-4 个 |
| 每子项 | 1 行 |
| 杂项工单（一次性修复、版本升级、小蜜单条） | 默认不写 |

### 6. 状态词标准化

- 已上线 / 已合入 / 已 merged / 已通过预发验收 / 已闭环
- 开发中 / 验收中 / 评审中 / 联调中
- 待合 / 待 prod / 待预发腾空

不要用模糊词："基本完成"、"差不多了"、"在推进"。

### 7. 关键标识——摘要标题用可点击链接

- 摘要中的 Aone 工单 / MR / CR：写成 `[Aone 83346651](url)` / `[MR !28231014](url)` / `[CR !28205668](url)` 的**简洁可点击链接**形式，不要裸号
- 对外发布物（GitHub PR）：带 markdown 链接
- **不必给出分支名**

## 数据采集

### 本仓

```bash
git log --since="YYYY-MM-DD" --pretty=format:"%h %ad %s" --date=short --no-merges
ls -lat runs/
bootstrap/week.sh   # 优先,基于 Aone jarvis-done 真源
```

`bootstrap/week.sh`、项目看板和标题搜索只生成候选清单，不直接形成个人周报。对候选 Aone 逐条读取详情与评论，建立“本人动作 → 实际结果”的证据链：

```bash
bin/a1id -- project workitem get <id> -f json
bin/a1id -- project workitem comment list <id> -f json
```

按评论时间过滤统计周期，先找汇报主体本人的动作，再核对动作之后的处理结果与当前状态。主单、研发关联单和 PR 描述同一交付时合并为一项，禁止重复计数。

### 跨仓

```bash
bin/a1id -- staff list <花名>                                                          # 拿工号
bin/a1id -- events user <工号> --since YYYY-MM-DD --until YYYY-MM-DD --per-page 100 --type push
bin/a1id -- events user <工号> --since YYYY-MM-DD --until YYYY-MM-DD --per-page 100 --type merge-request
```

只关心 `config/workspaces.json` 登记的仓。

### 身份去重

- 先用 `staff list` 确认汇报主体工号，再把已验证的花名、英文名、邮箱前缀、代码平台用户名归并为同一人。
- jarvis / open-jarvis / Terraform-研发数字人（`WORKER_xxx`）— 独立服务账号；不能仅凭账号执行结果归因给汇报主体，必须通过 Aone 评论建立汇报主体本人动作与后续结果的因果链。
- Jarvis 代码账号（蚂蚁内部 `admin.for.jarvis@antfin.com`）— 不相关，不写

### 归因审计表

草稿前先在内部形成审计表；表格不必写入最终钉钉周报：

| 候选事项 | 本人参与证据 | 后续结果证据 | 结论 |
|---|---|---|---|
| Aone / PR | 时间 + 动作 + 链接 | 时间 + 状态/测试/交付 + 链接 | 计入 / 排除 |

只有结论为“计入”的事项才能进入周报和 OKR。若证据不足，写“未计入”，不要用推测补齐。

## 输出格式（钉钉文档）

- 一级方向用 `**xxx**` 段落标题（不用 `#`/`##`/`###`）
- 二级用标准 `-` bullet（不用 `●`/`○`/`■`）
- 整篇用 `:::` 包钉钉容器块
- 表格慎用（钉钉 `[...]`/`{...}` 会被吞）

### 范本（gold standard）

```
:::
# **重要事项**

**MCP Server RunIaC 上线**
- **RunIaC 上线**：6-13 ~ 6-25 持续推进，已通过预发验收。
- **MCP token bizid 隔离**：开发中，已补 token / McpToken 单测覆盖。
- **RunIaC 错误去重**：6-26 新开，验收中。

**工具体系对内门户 / PlayGround 上线**
- **PlayGround 体验优化**：工具卡对齐 / 长表格横滚 / 输入框增高 / 新会话引导 / sessionId 复制 / 文件树折叠 / tool 事件回放 / 首页转静态，已上线。PlayGround 主动探测 MCP token 健康状态，连接失败 / 不可用 / 需认证三态透出，已合入。
- **沙箱 / PrivateLink / 凭证策略**：放开预发 MCPServer、PrivateLink 文档、凭证前缀去状态复述改 MCP-only + 明文凭证轮转提示。
- **Playground 访问日志**：已开发，[Aone 83346651](https://project.aone.alibaba-inc.com/v2/project/2100304/req/83346651)。

**Terraform AutoPilot 能力建设**
- **Jarvis 自治系统从 0 到 1**（terraflow/jarvis）。从 6-22 起仓库从零搭建，5 天内落 200+ 提交，覆盖 supervised 授权关口、Aone 唯一真源、并发认领锁、子代理编排、状态看板、worktree+PR 纪律全链路；具备无人值守 triage 到预发的闭环能力。

```

## 写入流程

1. 采集候选 → 做个人归因审计 → 归纳价值方向。
2. 草稿先在对话内呈现，**不直接写文档**；用户当面授权直接写时可跳过草稿确认。
3. 用户提供钉钉文档 URL 时，必须调用 `dingtalk-doc-rw`，先 `read_doc` 读取现状，再做最小范围更新；整篇回写时开启 `sanitize_round_trip=True`。
4. 写入后必须再次 `read_doc`，核对新增标题、关键链接与原有内容均保留。
5. 用户要求同步 OKR 时，复用同一份归因审计结果，选择语义匹配的 Objective 新增进展，并登记周报链接；没有明确量化依据时，不主观修改 KR 百分比。

## 对照表：AI 草稿易写错 vs 终稿保留

每次写完后按此自检；有系统性新差异回写本表。

| 草稿（AI 易写） | 终稿（保留） |
|---|---|
| 按仓库分块，每仓一段 | 按价值方向，跨仓合并 |
| 7-8 个一级方向 | 3-5 个 |
| Jarvis 自治写 6 子项展开 | 一句话 + "近一周多个需求已通过 Jarvis 交付" |
| 列所有杂项工单 | 删杂项，只留主线 |
| 项目共有 38 项、15 项在途，全部写成个人工作 | 仅保留本人参与且参与后产生结果的事项 |
| 服务账号完成代码或测试，就归因给汇报主体 | 必须存在汇报主体本人的明确动作及其后的对应结果 |
| 本人只同步控制面状态，也算交付推进 | 排除纯状态同步；只有业务结果由本人推动时才计入 |
| 本人未写代码却写“完成开发” | 按证据写“推动评审/验收/决策收口” |
| 加"未完待办"段 | 不加 |
| 加"其他工单交付"段 | 不加 |
| 用 ●/○ 字符 bullet | `**粗体**` + `-` |
| 一级用 `### xxx` | 用 `**xxx**` |
| 裸 Aone 号 + 分支名 | `[Aone xxx](url)` 简洁链接，不带分支名 |

## 红线

1. **不带 AI 署名**：周报对外，禁出现「🤖 Generated with Claude Code」「Co-Authored-By: Claude」等任何 AI 水印（CLAUDE.md 工作纪律 #5）；commit / PR / 钉钉文档正文都不带
2. **回读校验**：钉钉文档写入后必须 `read_doc` 回读，确认渲染正常
3. **草稿先于写入**：除非用户当面授权直接写文档，否则草稿先在对话内呈现
4. **禁止扩大归因**：项目级成果、服务账号产出和他人交付不得在缺少个人因果证据时写成汇报主体的工作
