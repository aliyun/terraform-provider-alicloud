# alicloud_cms_escalation_policy

Provides a Cms Escalation Policy resource.

An incident escalation policy defines the rules that escalate incidents through notification channels after specified delays. Each stage in the policy can notify different channels, receivers, and target incident states.

For information about Cms Escalation Policy and how to use it, see [What is Escalation Policy](https://next.api.alibabacloud.com/document/Cms/2024-03-30/CreateEscalationPolicy).

-> **NOTE:** Available since v1.297.0.

## Example Usage

Basic Usage

```terraform
variable "name" {
  default = "terraform-example"
}

resource "alicloud_log_project" "default" {
  project_name = var.name
}

resource "alicloud_cms_workspace" "default" {
  workspace_name = var.name
  sls_project    = alicloud_log_project.default.project_name
}

resource "alicloud_cms_escalation_policy" "default" {
  workspace   = alicloud_cms_workspace.default.workspace_name
  name        = var.name
  enable      = true
  description = "Terraform managed escalation policy"

  escalation_stage_list {
    index                 = 1
    cycle_notify_interval = 5
    cycle_notify_count    = 3
    trigger_delay         = 10
    target_incident_state = "acknowledged"

    notify_channels {
      channel_type         = "DING"
      receivers            = ["tf-test-group"]
      enabled_sub_channels = []
    }

    effect_time_range {
      time_zone            = "Asia/Shanghai"
      start_time_in_minute = 0
      end_time_in_minute   = 1439
      day_in_week          = [1, 2, 3, 4, 5]
    }
  }
}
```

## Argument Reference

The following arguments are supported:

* `workspace` - (Required, ForceNew) The name of the workspace to which the escalation policy belongs.
* `name` - (Optional) The name of the escalation policy.
* `description` - (Optional) The description of the escalation policy.
* `enable` - (Optional) Whether the escalation policy is enabled.
* `escalation_stage_list` - (Required) The list of escalation stages. Each stage defines the notification and timing behavior when an incident escalates. See [`escalation_stage_list`](#escalation_stage_list) below.

<a name="escalation_stage_list"></a>

### `escalation_stage_list`

The `escalation_stage_list` block supports:

* `index` - (Optional) The sequence index of the escalation stage.
* `cycle_notify_interval` - (Optional) The interval, in minutes, between repeated notifications within this stage.
* `cycle_notify_count` - (Optional) The maximum number of repeated notifications within this stage.
* `trigger_delay` - (Optional) The delay, in minutes, before this stage is first triggered during escalation.
* `target_incident_state` - (Optional) The target incident status that the escalation policy ends at.
* `notify_channels` - (Optional) The notification channels for this stage. See [`escalation_stage_list.notify_channels`](#escalation_stage_list.notify_channels) below.
* `effect_time_range` - (Optional) The time range during which the escalation notification takes effect. See [`escalation_stage_list.effect_time_range`](#escalation_stage_list.effect_time_range) below.

<a name="escalation_stage_list.notify_channels"></a>

### `escalation_stage_list.notify_channels`

The `escalation_stage_list.notify_channels` block supports:

* `channel_type` - (Optional) The type of the notification channel, such as `DING`.
* `receivers` - (Optional) The list of receiver identifiers, such as contact group names.
* `enabled_sub_channels` - (Optional) The list of enabled sub-channels for the contact, such as the notification types supported by a contact.

<a name="escalation_stage_list.effect_time_range"></a>

### `escalation_stage_list.effect_time_range`

The `escalation_stage_list.effect_time_range` block supports:

* `time_zone` - (Optional) The time zone of the effect time range, such as `Asia/Shanghai`.
* `day_in_week` - (Optional) The days of the week (1-7) on which the escalation notification takes effect.
* `start_time_in_minute` - (Optional) The start time of the day, in minutes (0-1439).
* `end_time_in_minute` - (Optional) The end time of the day, in minutes (0-1439).

## Attributes Reference

The following attributes are exported:

* `id` - The ID of the resource. It is formatted as `<uuid>:<workspace>`.
* `uuid` - The UUID of the escalation policy, generated by the server.
* `create_time` - The creation time of the resource.
* `update_time` - The last modified time of the resource.

## Timeouts

The `timeouts` block allows you to specify [timeouts](https://developer.hashicorp.com/terraform/language/resources/syntax#operation-timeouts) for certain actions:

* `create` - (Defaults to 5 mins) Used when create the Escalation Policy.
* `delete` - (Defaults to 5 mins) Used when delete the Escalation Policy.
* `update` - (Defaults to 5 mins) Used when update the Escalation Policy.

## Import

Cms Escalation Policy can be imported using the id, e.g.

```shell
$ terraform import alicloud_cms_escalation_policy.example <uuid>:<workspace>
```
